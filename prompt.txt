Current observed behavior:
- Straight-line mapping is much better than before.
- However, after making a large loop and returning, the trajectory/map can still tilt in +Y direction.
- This now looks less like pure IMU prior failure and more like loop correction / global heading stabilization weakness.
- False loop closures must be avoided very conservatively.

Important context:
- User does NOT want to rush into slam_toolbox integration because it would force broad ROS/MQTT/Viz contract changes.
- Preferred direction is to keep improving our own slam mapper incrementally.
- External algorithm/library adoption is still on the table, but only selectively and carefully.
- We discussed possibly promoting amr_slam_mapper into a more independent package/repo later, likely under a name like ros-slam-mapper.

Constraints / preferences:
- Keep changes narrow and testable.
- Avoid breaking existing AMR contracts.
- Be conservative with loop closure logic.
- If trying a new loop-related idea, define explicit fail/pass criteria first.
- Use Korean in user-facing explanations.
